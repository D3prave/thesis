\chapter{Experimental Design and Implementation}
\label{ch:experimental_design}

Chapter~\ref{ch:semantic_entropy} defines the estimators. This chapter states
what was run: every setting that can change a reported number and every
departure from Farquhar et al.~\cite{semantic_entropy_nature_2024}.

The released code~\cite{kossen_semantic_uncertainty_code_2024} is the
reference implementation. Section~\ref{sec:deviation-register} distinguishes
its behavior from the paper's description and records this study's changes.
Two implementation details change the measured quantity: the clustering
procedure and the scoring of P(True).

For each prompting condition, temperature and seed, a generator produced one
set of answers. These saved answers were then clustered, graded and scored in
different ways. Within each set, a comparison changes only the selected
entailment model, correctness rule or estimator. Changing the prompt or
temperature requires a new set of answers.
Within a fixed prompting condition, entailment model, correctness rule,
estimator and temperature, a \emph{cell} is one dataset--generator--seed
combination. The three seed cells for one dataset--generator pair form one
independent statistical \emph{unit}.

\paragraph{Which questions are evaluated.} The released code uses one seeded
random sequence for three selections. It first chooses five worked examples,
then twenty examples for P(True), and finally the evaluation questions. Because
each selection advances the same sequence, their order determines which
questions are evaluated. The final selection draws 400 questions per split,
except that SVAMP's validation split contains only 300. The selected questions
are fixed across run seeds, so every model and seed answers the same questions.
Appendix~\ref{app:random-selection} shows the selection order in code.

\paragraph{TriviaQA evaluation sets are 378 questions, not 400.} The
SQuAD-format conversion stores one row per question and context pair, so questions
recur. The released split therefore puts \textbf{16 questions in both the
training and the evaluation split}, with 9 more repeated inside training and 6
inside evaluation. All were removed identically from every method's evaluation,
leaving \textbf{391 training and 378 evaluation questions}. NQ-Open and SVAMP
have no repeats. This is a defect inherited from the released loader, not one
introduced here.

The two 0-shot conditions isolate the instruction's effect: both omit worked
examples, so only the instruction changes. Supplementary Note~7 of the original
introduces the five examples while describing the short-phrase condition and
says that they ``further encourage the LLM to predict with brevity''. The full
$2\times2$ design tests the instruction and the worked examples separately.

\paragraph{Prompt format.} Prompts are plain completions: one brief
instruction, then \texttt{Question:\ \ldots} and \texttt{Answer:\ \ldots}
blocks for any worked examples, then the query left open at \texttt{Answer:}.
No chat template and no system message is applied, even for the
instruction-tuned models, because that is what the released code does.
Generation stops at whichever of the released \texttt{STOP\_SEQUENCES} occurs
earliest in the output, in practice the single newline, or at the tokenizer's
end-of-sequence token.

The design has two limits. Both shortest-answer conditions are 5-shot, so answer
length and example count are separated only among the longer answers. The two
added conditions were collected only at $T=1.0$ with the default short-answer
entailment model, so the full $2\times2$ comparison is limited to that setting.

\paragraph{The ten samples.} For each question the model is sampled $M=10$
times at temperature $T=1.0$, top-$p$ $0.9$, top-$k$ $50$, under a budget of at
most \textbf{50 new tokens}, which is the released code's default. The entropy estimators are computed from these
samples and nothing else. Per-sequence log-likelihoods are captured and
length-normalized, which is what makes the probability-weighted estimators
available.

\paragraph{The most-likely answer.} One extra answer per question is graded for
correctness, judged by P(True), and used for the probe feature. Despite its
name, it is not a greedy decode. The released code draws it as a sample at
temperature $0.1$ with \texttt{do\_sample=True}.

This answer has a 256-token budget, while each of the ten entropy samples has a
50-token budget. Correctness can therefore be judged on an answer about five
times longer than the answers used to estimate uncertainty. This changes the
evaluation setup relative to a shared token budget. The longer answers observed
here are reported in Section~\ref{sec:reproduction}, with the detailed
answer-length check in Appendix~\ref{app:collection-checks}.

\paragraph{Seeds.} Three run seeds (42, 43, 44) vary sampling only. The worked
examples and evaluated questions are fixed, so the seeds are repeated samples
from one setting rather than independent replications. Section~\ref{sec:statistics}
explains how the analysis accounts for this dependence.

\section{The temperature sweep}
\label{sec:temperature-sweep}

The two conditions the original uses, \texttt{chat\_0shot} and
\texttt{default\_5shot}, were also collected at temperatures $0.1$, $0.3$,
$0.5$ and $0.7$, alongside the main setting of $1.0$. That sweep covers two
entailment models, the default model and \texttt{Qwen2.5-72B-Instruct}, and the
five entropy estimators. The two added conditions, the
\texttt{nli-deberta-v3-large} entailment model, the probes and P(True) are not
in the sweep. Probe-feature collection was disabled during the sweep,
which introduced a defect with the following limits:

\begin{itemize}
  \item \textbf{The estimators are unaffected.} Every entropy score is computed
    from the ten samples, which the defect does not touch.
  \item \textbf{The LLM-judge labels are unaffected.} They are joined to each
    record by \texttt{prompt\_id} from one grading pass over the main
    collection, so they describe the same temperature-$0.1$ answer at all
    five temperatures.
  \item \textbf{The token-F1 labels are affected.} With feature collection off,
    no most-likely answer is written, and the correctness routine falls through
    to the modal sampled answer. Sweep cells therefore grade the modal sample
    \emph{at the sweep temperature}, rather than the fixed answer used by
    the LLM graders.
  \item \textbf{Answer length is affected} for the same reason, and means
    different things in different rows. Only the temperature-$1.0$ rows are
    comparable.
\end{itemize}

Two consequences hold throughout: the sweep is quoted only under LLM grading,
and no statement about answer length is drawn from a sweep row. The numerical
checks are preserved in Appendix~\ref{app:collection-checks}.

The sweep is also not a test of Kuhn et al.'s intermediate-temperature
optimum~\cite{kuhn_semantic_uncertainty_2023}. There, lowering the temperature
also changed the accuracy of the answer being judged; here the graded answer is
held outside the sweep, so only the diversity side of that trade-off can move.

\section{Evaluation metrics}
\label{sec:evaluation-metrics}

The framework is \emph{selective prediction}. The uncertainty score is a
ranking signal, and the records ranked most uncertain are the ones a deployment
would reject or check more expensively.

\begin{itemize}
  \item \emph{AUROC}. Treating ``incorrect'' as the positive class, AUROC is
        the probability that a randomly chosen incorrect record gets a higher
        uncertainty score than a randomly chosen correct one, with tied scores
        counting as one half. Here $0.5$ is
        random and $1.0$ is perfect. It depends only on the ranking, so the
        unit of the entropy does not matter. This is the metric that isolates
        the detector, and the one this thesis leads with.
  \item \emph{Rejection-accuracy curve}. For each rejection fraction $f$, the
        accuracy on the remaining $1-f$ of records after discarding the $f$
        most uncertain. A useful signal makes the curve rise above the flat
        raw-accuracy line.
  \item \emph{AURAC}, the area under that curve, reported in \textbf{two
        definitions} in a secondary analysis. They are not directly comparable,
        and the released code uses the first:
        \begin{itemize}
          \item \texttt{aurac\_paper}: twenty retention quantiles from $0.1$,
            with $dx = 0.9/19$, unnormalized. Maximum attainable about $0.947$.
          \item \texttt{aurac\_mean\_retained}: mean retained accuracy averaged
            over all retention levels.
        \end{itemize}
\end{itemize}

Unlike AUROC, both AURAC definitions depend on how accurate the generator was
to begin with, so their values are comparable only within one task and model.
Appendix~\ref{sec:aurac-disagreement} reports the comparison with AUROC and
the differences between these two definitions.

\paragraph{A worked example.} Suppose a detector scores five answers, three
correct (C) and two wrong (W):

\begin{center}\small
\begin{tabular}{lccccc}
\toprule
Answer & \#1 & \#2 & \#3 & \#4 & \#5 \\
\midrule
Detector score & 0.10 & 0.20 & 0.25 & 0.30 & 0.90 \\
Actually & C & C & W & C & W \\
\bottomrule
\end{tabular}
\end{center}

\emph{AUROC by hand.} Form every (wrong, correct) pair; there are $2 \times 3 =
6$. The wrong answer scores higher in five of them; the exception is
(\#3, \#4), where the wrong answer \#3 ($0.25$) scores below the correct answer
\#4 ($0.30$). So AUROC $= 5/6 \approx 0.83$.

\emph{Rejection accuracy by hand.} Start from the raw accuracy, $3/5 = 0.60$.
Reject the highest-scoring answer (\#5, wrong) and accuracy rises to
$3/4 = 0.75$. Reject the next (\#4, correct) and it dips to $2/3 \approx 0.67$, because a
good answer was thrown away. Reject the next (\#3, wrong) and it
reaches $2/2 = 1.00$; rejecting \#2 leaves the correct answer \#1, so the last
non-empty set is also $1.00$. The curve is $0.60, 0.75, 0.67, 1.00, 1.00$, and
averaging over those five levels gives $0.803$. For both metrics, higher is
better.

Raw answer accuracy is reported as context only. It is not a measure of the
detector.

\section{Statistical procedure}
\label{sec:statistics}

\paragraph{Nine units, not twenty-seven cells.} A fixed short-answer setting
has 27 cells: three datasets by three generators by three seeds. The seed cells
within one dataset--generator pair are repeated samples, not independent
observations. The analysis therefore uses \textbf{nine independent units}, one
for each dataset--generator pair. Treating all 27 cells as independent would
overstate the amount of evidence. The numerical resampling check is reported
with the Results in Section~\ref{sec:se-vs-surface}.

\paragraph{Paired tests resample units and records.} Three resampling methods
are available, and they capture different sources of variation:

\begin{itemize}
  \item \texttt{units}: resample the nine dataset--generator units with
    replacement while holding prompts fixed. This captures only variation
    between units.
  \item \texttt{records}: hold units fixed and resample prompts within each
    cell. The pairing ensures that both estimators always score the same
    prompts. This captures only variation within cells.
  \item \texttt{hier}: resample units and then prompts within each selected
    cell. This captures both sources of variation.
\end{itemize}

For each method, the statistic first averages the paired AUROC difference over
seeds within each unit and then averages over the nine units. The reported
95\,\% percentile intervals use 2{,}000 hierarchical resamples. Resampling
prompts alone does not include variation between dataset--generator units and
cannot describe uncertainty across a wider population of tasks.

\paragraph{Other intervals.} Cell-level summaries use 95\,\% bootstrap
intervals from 2{,}000 cell resamples. When several cells in one condition are
tested together, Holm's step-down procedure~\cite{holm_simple_1979} controls
the chance of any false positive in that family. It is less conservative than
the Bonferroni correction while providing the same control. The released code
uses 90\,\% bias-corrected and accelerated (BCa) intervals from 1{,}000
resamples, so its intervals are not directly comparable with those computed
here.

\paragraph{Cross-seed spread.} A $\pm$ value on a per-cell number is the
standard deviation over the three run seeds. With three seeds that shows
stability, not significance, and it is kept separate from the bootstrap
intervals. Results report the observed range across seeds so that readers can
compare it with the differences between methods.

\section{Where this study differs from the original}
\label{sec:deviation-register}

A replication must state both how the released code differs from the paper
and how this study differs from both. Table~\ref{tab:code-divergence} records
nine implementation details, including differences, clarifications and the
most-likely-answer token-budget exception. Table~\ref{tab:deviation-register}

Both full registers are in Appendix~\ref{app:deviation-registers}.

The main validity concerns are stated in the sections where they matter. This
study uses open models in place of proprietary judges, has no human correctness
labels, evaluates three of the original five question sets, and uses strict
entailment for paragraphs instead of the original relaxed rule. It also adds
string-based entropy baselines, multiple entailment models and correctness
rules, four prompting combinations, five temperatures and three sampling
seeds.

Two defects are inherited rather than introduced: token-F1 grading, whose
behavior on verbose answers is quantified in
Section~\ref{sec:correctness-comparison}, and the TriviaQA split contamination
described in Section~\ref{sec:datasets}.

\section{Implementation and provenance}
\label{sec:hpc-execution}

The code stores generation, clustering and grading outputs separately. Jobs
record the code revision and experiment settings, and check the requested
clustering settings before accepting an output. This makes it possible to
repeat an analysis without generating new answers.

Appendix~\ref{app:hpc-details} describes the computing resources, libraries,
job checks and stored metadata. Appendix~\ref{app:schema} describes the
measurement package and the limits of what it can reproduce without the
underlying record files.
