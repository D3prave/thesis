\chapter{Experimental Design and Implementation}
\label{ch:experimental_design}

This chapter says what was run. It is written to be checkable: every setting
that could change a reported number is stated, and every departure from
Farquhar et al.~\cite{semantic_entropy_nature_2024} is listed in
Section~\ref{sec:deviation-register} rather than left to be inferred.

Two conventions run through the design. First, the study is built against the
authors' released code~\cite{kossen_semantic_uncertainty_code_2024}, and where
the published prose and that code disagree, the code is followed. The object of
study is the method as a reader would obtain it. The gaps are not
hypothetical. There are nine points where the code either departs from the
published description or settles a detail the description leaves open, and two
of them change what the reported quantity is: the clustering procedure, and the
scoring of P(True). Second, generation happened once. Clustering, correctness
labelling and scoring are all applied afterwards to those stored generations,
so the entailment model, the correctness rule and the estimator can each be
varied while everything else stays fixed by construction rather than by
matching.

\paragraph{Which questions are evaluated.} The selection reproduces
\texttt{generate\_answers.py} rather than taking a prefix of the split. The
detail matters because three draws share one random stream, so the draw order
decides which questions are evaluated. The released code parameterizes the four
constants; they are shown here at this study's values:

\begin{quote}\footnotesize
\begin{verbatim}
random.seed(10)
prompt_indices = random.sample(answerable_indices, 5)
remaining = list(set(answerable_indices)
                 - set(prompt_indices))
p_true_indices = random.sample(answerable_indices, 20)
remaining = list(set(remaining) - set(p_true_indices))
for split in ("train", "validation"):
    indices = random.sample(list(possible_indices),
                            min(400, len(dataset)))
\end{verbatim}
\end{quote}

This draws 400 questions per split, except that SVAMP's validation split holds
only 300, so all 300 are taken. The selection is fixed across run seeds, so
every model and seed answers the same questions and all comparisons between
them are paired.

\paragraph{TriviaQA evaluation sets are 378 questions, not 400.} The
SQuAD-format conversion stores one row per question and context pair, so questions
recur. The released split therefore puts \textbf{16 questions in both the
training and the evaluation split}, with 9 more repeated inside training and 6
inside evaluation. All were removed identically from every method's evaluation,
leaving \textbf{391 training and 378 evaluation questions}. NQ-Open and SVAMP
have no repeats. This is a defect inherited from the released loader, not one
introduced here.

The isolating contrast is the pair of 0-shot corners, where the example count
is held at zero and only the instruction changes. Supplementary Note~7 of the
original introduces the five examples while describing the short-phrase
condition, remarking that they ``further encourage the LLM to predict with
brevity''; the factorial makes it possible to ask whether that is a detail or
the variable that matters.

\paragraph{Prompt format.} Prompts are plain completions: one brief
instruction, then \texttt{Question:\ \ldots} and \texttt{Answer:\ \ldots}
blocks for any worked examples, then the query left open at \texttt{Answer:}.
No chat template and no system message is applied, even for the
instruction-tuned models, because that is what the released code does.
Generation stops at whichever of the released \texttt{STOP\_SEQUENCES} occurs
earliest in the output, in practice the single newline, or at the tokenizer's
end-of-sequence token.

Two limits are worth stating now. Both 11-character corners are 5-shot, so the
design separates length from example count only at the long end. And the two
added corners were collected on one entailment backend and one temperature, so
the factorial can only be estimated on a single clustering model, and not on
the backend most favorable to semantic entropy.

\paragraph{The ten samples.} For each question the model is sampled $M=10$
times at temperature $T=1.0$, top-$p$ $0.9$, top-$k$ $50$, under a budget of at
most \textbf{50 new tokens}, which is the released code's default. The entropy estimators are computed from these
samples and nothing else. Per-sequence log-likelihoods are captured and
length-normalized, which is what makes the probability-weighted estimators
available.

\paragraph{The most-likely answer.} One extra answer per question plays a
different role: it is what correctness is scored on, what P(True) judges, and
where the probe feature is read. It is \emph{not} a greedy decode. Following
\texttt{generate\_answers.py}, which sets
\texttt{temperature = 0.1 if i == 0 else args.temperature} with
\texttt{do\_sample=True}, it is a temperature-$0.1$ sample. It is drawn under a
\textbf{256-token} budget rather than the 50 the samples get, inherited from
the probe-feature path.

That asymmetry is one-sided and it matters, so it belongs in the main text. The
estimators see answers capped at 50 tokens, while correctness is judged on an
answer allowed about five times that. It is the main
reason the sentence-length condition here averages 255.2 characters against the
95.6 the original reports, and it falls hardest on Llama-3.1-8B, whose
most-likely answers reach a cell mean of 826.3 characters.

\paragraph{Seeds.} Three run seeds (42, 43, 44) vary sampling only. The worked
examples and the evaluated question set are fixed across them, so a seed is a
repeat draw from one configuration rather than an independent replication.
Section~\ref{sec:statistics} draws the consequence.

\section{The temperature sweep}
\label{sec:temperature-sweep}

The two conditions the original uses, \texttt{chat\_0shot} and
\texttt{default\_5shot}, were also collected at temperatures $0.1$, $0.3$,
$0.5$ and $0.7$ alongside the canonical $1.0$, on the canonical backend and on
\texttt{Qwen2.5-72B-Instruct}, for the five entropy estimators. The two added
conditions, the \texttt{nli-deberta-v3-large} backend, the probes and P(True)
are not in the sweep. The sweep ran with probe-feature
collection switched off, and that switch introduced a defect whose reach is
bounded:

\begin{itemize}
  \item \textbf{The estimators are unaffected.} Every entropy score is computed
    from the ten samples, which the defect does not touch.
  \item \textbf{The LLM-judge labels are unaffected.} They are joined to each
    record by \texttt{prompt\_id} from one grading pass over the canonical
    collection, so they describe the canonical temperature-$0.1$ answer at all
    five temperatures. Verified bit-identical in 108 of 108 cells.
  \item \textbf{The token-F1 labels are affected.} With feature collection off,
    no most-likely answer is written, and the correctness routine falls through
    to the modal sampled answer. Sweep cells therefore grade the modal sample
    \emph{at the sweep temperature}. Measured: token-F1 accuracy differs from
    the canonical run in 54 of 54 cells, by $0.015$ on average in absolute
    terms and by at most $0.262$.
  \item \textbf{Answer length is affected} for the same reason, and means
    different things in different rows. Only the temperature-$1.0$ rows are
    comparable.
\end{itemize}

Two consequences hold throughout: the sweep is quoted only under LLM grading,
and no statement about answer length is drawn from a sweep row.

The sweep is also not a test of Kuhn et al.'s intermediate-temperature
optimum~\cite{kuhn_semantic_uncertainty_2023}. There, lowering the temperature
also changed the accuracy of the answer being judged; here the graded answer is
held outside the sweep, so only the diversity side of that trade-off can move.

\section{The long-form arm}
\label{sec:longform-design}

The long-form arm is a FactScore-style biography
task~\cite{min_factscore_2023}: the prompt is ``Tell me a bio of
\{entity\}.'' over a curated list of biography subjects, with each entity's
pinned English Wikipedia lead section, fetched from the MediaWiki summary
endpoint, as the reference. Each of the nine cells, three generators by three
seeds, holds 500 records. One caveat belongs here: the entity list committed to
this repository holds 308 subjects, which is fewer than the preparation script
would need for the split that produced these files, and the prepared data
itself is not version-controlled. The 500 records per cell are recorded in the
measurement package and are what the results are computed over, but the exact
entity list behind them cannot be reconstructed from the repository. This arm
is therefore the least reproducible part of the study. Generation is
checked at collection time to have a median sampled answer length of at least
300 characters, so the arm really is testing paragraph-length output.
Uncertainty is scored on the whole paragraph; correctness is judged per claim
by the Qwen2.5-72B-Instruct judge. Only that judge is available here, so this arm has no second grader as a
control. It is the one place where the two-roles concern of
Section~\ref{sec:correctness} is uncontrolled.

\paragraph{This arm does not implement the original's paragraph method.}
Farquhar et al.\ relax the clustering rule for paragraphs: two answers mean the
same thing ``if at least one of them entails the other and neither is seen to
contradict the other'', which their Methods section calls a \emph{non-defeating}
bidirectional entailment check. They adopt it because DeBERTa has lower recall
than the judges they compare against, and the caption of their Supplementary
Figure~1 says it is this variant that produces their DeBERTa result.

The difference is not a matter of interpretation. The released
\texttt{get\_semantic\_ids} takes a \texttt{strict\_entailment} flag, and the
two branches are different rules. With the flag set, both directions must
return entailment. Without it, and the default is without it, two answers count as
equivalent when neither direction returns contradiction and the two directions
are not both neutral. This study sets the flag in every arm, including this
one. So the divergence is a one-line configuration difference rather than a
difference of implementation. It has two consequences. The backend comparison
here is not a test of that figure. And a poor paragraph result from a
low-recall cross-encoder follows from the rule rather than from the model.

\section{Evaluation metrics}
\label{sec:evaluation-metrics}

The framework is \emph{selective prediction}. The uncertainty score is a
ranking signal, and the records ranked most uncertain are the ones a deployment
would reject or check more expensively.

\begin{itemize}
  \item \emph{AUROC}. Treating ``incorrect'' as the positive class, AUROC is
        the probability that a randomly chosen incorrect record gets a higher
        uncertainty score than a randomly chosen correct one. Here $0.5$ is
        random and $1.0$ is perfect. It depends only on the ranking, so the
        unit of the entropy does not matter. This is the metric that isolates
        the detector, and the one this thesis leads with.
  \item \emph{Rejection-accuracy curve}. For each rejection fraction $f$, the
        accuracy on the remaining $1-f$ of records after discarding the $f$
        most uncertain. A useful signal makes the curve rise above the flat
        raw-accuracy line.
  \item \emph{AURAC}, the area under that curve, reported in \textbf{two
        definitions}, because they are not comparable and the released code
        uses the first:
        \begin{itemize}
          \item \texttt{aurac\_paper}: twenty retention quantiles from $0.1$,
            with $dx = 0.9/19$, unnormalized. Maximum attainable about $0.947$.
          \item \texttt{aurac\_mean\_retained}: mean retained accuracy averaged
            over all retention levels.
        \end{itemize}
\end{itemize}

Unlike AUROC, both AURAC definitions depend on how accurate the generator was
to begin with, so their values are comparable only within one task and model.
Section~\ref{sec:aurac-disagreement} shows the dependence is strong enough to
matter, and that the two definitions do not rank the methods the same way as
AUROC or as each other.

\paragraph{A worked example.} Suppose a detector scores five answers, three
correct (C) and two wrong (W):

\begin{center}\small
\begin{tabular}{lccccc}
\toprule
Answer & \#1 & \#2 & \#3 & \#4 & \#5 \\
\midrule
Detector score & 0.10 & 0.20 & 0.25 & 0.30 & 0.90 \\
Actually & C & C & W & C & W \\
\bottomrule
\end{tabular}
\end{center}

\emph{AUROC by hand.} Form every (wrong, correct) pair; there are $2 \times 3 =
6$. The wrong answer scores higher in five of them; the exception is
(\#3, \#4), where the wrong answer \#3 ($0.25$) scores below the correct answer
\#4 ($0.30$). So AUROC $= 5/6 \approx 0.83$.

\emph{Rejection accuracy by hand.} Start from the raw accuracy, $3/5 = 0.60$.
Reject the highest-scoring answer (\#5, wrong) and accuracy rises to
$3/4 = 0.75$. Reject the next (\#4, correct) and it dips to $2/3 \approx 0.67$, because a
good answer was thrown away. Reject the next (\#3, wrong) and it
reaches $2/2 = 1.00$; rejecting \#2 leaves the correct answer \#1, so the last
non-empty set is also $1.00$. The curve is $0.60, 0.75, 0.67, 1.00, 1.00$, and
averaging over those five levels gives $0.803$. For both metrics, higher is
better.

Raw answer accuracy is reported as context only. It is not a measure of the
detector, and Section~\ref{sec:aurac-disagreement} shows how strongly the AURAC
definitions are governed by it.

\section{Statistical procedure}
\label{sec:statistics}

\paragraph{Nine units, not twenty-seven cells.} A short-answer configuration
has 27 cells: three datasets by three generators by three seeds. It does not
have 27 independent observations. The seeds sit inside each (dataset,
generator) pair and vary sampling alone, so the design carries \textbf{nine
independent units}. Seeds account for about $15\,\%$ of the variance of the
semantic-minus-surface contrast and the differences between units for the rest.
Treating the cells as independent inflates the number of contrasts that look
significant by roughly a third: across the 336 pairwise comparisons of the
register, 171 resolve when units are resampled, against about 230 when the 27
cells are treated as independent.

\paragraph{Every paired test resamples units as well as records.} This is a
commitment of the thesis, not a detail of one table. Three resampling schemes
are available for a paired comparison, and they answer different questions:

\begin{itemize}
  \item \texttt{units}: resample the nine (dataset, model) units with
    replacement, holding records fixed. Uses only the between-unit variance.
  \item \texttt{records}: hold units fixed and resample records inside each
    cell, paired so both estimators always score the same prompts. Uses only
    the within-cell variance.
  \item \texttt{hier}: resample units, then records inside each drawn cell.
    Carries both.
\end{itemize}

In each scheme the statistic is the mean over units of the mean-over-seeds
paired AUROC difference, with 95\,\% percentile intervals over 2{,}000
resamples. The \texttt{hier} scheme is what this thesis reports. That is not a
preference: Section~\ref{sec:se-vs-surface} shows \texttt{records} alone gives
intervals about three times too narrow and reverses the direction of the
conclusion, because it treats several hundred correlated questions from one
dataset as several hundred independent pieces of evidence about a population of
tasks. That is itself a result, and it is reported as one.

\paragraph{Other intervals.} Intervals reported over cells are 95\,\% bootstrap
intervals resampling cells, 2{,}000 iterations. Where several cells within one
condition are tested as a family, Holm's step-down
procedure~\cite{holm_simple_1979} controls the family-wise error rate; it is
preferred to Bonferroni because it gives the same rate while rejecting at least
as often. The released code's own intervals are 90\,\% BCa over 1{,}000
resamples, so intervals quoted from the original and computed here are not
directly comparable.

\paragraph{Cross-seed spread.} A $\pm$ value on a per-cell number is the
standard deviation over the three run seeds. With three seeds that shows
stability, not significance, and it is kept separate from the bootstrap
intervals. It also gives the scale for judging a margin: effects below about
$0.025$ AUROC are inside the seed range for the entropy estimators.

\section{Data properties worth knowing}
\label{sec:data-properties}

Facts about the recorded data, not conclusions.

\begin{itemize}
  \item \textbf{The LLM entailment backend is not bitwise reproducible.}
    Batching in the inference engine moves a small fraction of entailment
    verdicts between two runs of the same cell. The cross-encoders are
    deterministic.
  \item \textbf{Truncation.} A sample that reaches its 50-token ceiling before
    a stop sequence is truncated, which can distort the entropy computed over
    it. The rate was measured on an earlier collection at a different sample
    size and not recomputed for this one, so no figure is quoted.
  \item \textbf{Coverage is not uniform.} The two added prompting conditions
    exist on one backend and one temperature; the temperature sweep covers the
    entropy estimators only, on the original's two conditions and two of the
    three backends; and the probes and P(True) were collected under
    different backends, so those two are never compared directly. Each table in
    Chapter~\ref{ch:results} states its own coverage.
\end{itemize}

\section{Implementation and HPC execution}
\label{sec:hpc-execution}

The work used the NHR@FAU computing center: its GPU cluster \emph{Alex} (NVIDIA
A100 nodes) for generation and all GPU-heavy steps, and its CPU cluster
\emph{Fritz} for the lighter post-hoc reclustering.

\paragraph{Code and libraries.} All code, configuration and batch scripts live
in a small Python package installed with \texttt{uv}, targeting Python~3.11+.
Generation runs on the HuggingFace \texttt{transformers} path, because the
probe features are read in the same pass and vLLM does not expose the hidden
states a probe needs. vLLM is used for the LLM entailment backend and the LLM
judges, where only the generated text is needed. Clustering uses the cross-encoders and the LLM
judge of Section~\ref{sec:backends}, and the probes use scikit-learn. The
pipeline reads a processed dataset, samples $M$ answers per prompt, clusters
them with the configured backend, computes the entropy scores, attaches a
correctness label and writes one JSONL record per prompt;
Appendix~\ref{app:schema} reproduces the schema.

\paragraph{What ran where.} Generation and clustering ran on Alex: one A100 for
the 7B and 8B models, four A100-80GB GPUs with the model sharded across them
for the 70B model, with the cross-encoder on CPU so the GPUs stayed free. Post-hoc
cross-encoder reclustering ran on Fritz; the Qwen2.5-72B judge, being itself a
72B model, ran on Alex. All GPU work went through the Slurm batch scheduler.

\paragraph{Provenance.} All artifacts were produced at one pinned commit,
recorded in each cell's \texttt{job\_meta.json} as
\texttt{analysis\_code\_commit}. Every collection job checks that the
repository HEAD matches that commit and that the tracked working tree is clean
before generating anything, and refuses to start otherwise. Each
\texttt{job\_meta.json} also records the Slurm job id, host, model, dataset,
decoding parameters, seed and input path. Code, configuration, result
tables and figures are version-controlled; model caches, raw generations and
hidden states live in separate project storage.
Appendix~\ref{app:reproducibility} lists the manifest digests.

\paragraph{Analysis is separable from the runs.} Every number in
Chapter~\ref{ch:results} is recomputed from the saved per-record files by one
aggregation step, with nothing carried over from an intermediate table, so an
error in an earlier aggregation cannot reach a reported figure. Each
reclustering job also checks its own output before exiting: if any record's
clustering rule, closure, clustering input, entailment input format or
question-conditioning flag differs from what the job was asked for, the job
fails rather than writing a cell that is quietly off-protocol.
