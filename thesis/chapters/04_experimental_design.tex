\chapter{Experimental Design}

This chapter specifies the experimental design used to evaluate whether
semantic entropy provides a better hallucination and abstention signal
than surface-form uncertainty. The design is split into two phases. Phase
1 establishes an exact-match clustering baseline that is small enough to
debug locally before being run at evaluation scale. Phase 2 repeats the
same measurement plan with NLI clustering on NHR@FAU resources, with Alex
used for the primary GPU runs and Fritz for posthoc CPU reclustering and KLE.
Helma remained outside the recorded execution scope. Chapter 3
defines the semantic entropy method itself; this chapter fixes the
experimental variables, comparisons, and records; Chapter 5 covers execution,
storage, and reproducibility.

\section{Research Question}

The main question is whether uncertainty over semantic answers identifies
incorrect or unreliable generations better than uncertainty over sampled
strings. The target phenomenon is semantic uncertainty or confabulation,
not every form of hallucination. This follows the distinction made in the
semantic entropy literature: a model can be wrong because it is
semantically uncertain, but it can also be confidently and systematically
wrong \cite{semantic_entropy_nature_2024,
kalai_why_language_models_hallucinate_2025,simhi_choke_2025}.

\section{Datasets}

The first datasets are TriviaQA and SVAMP. TriviaQA provides open-domain
question answering examples with short factual answers
\cite{joshi_triviaqa_2017}. SVAMP provides math word problems for which
answer normalization and semantic equivalence matter, particularly for
numeric or near-numeric answers \cite{patel_svamp_2021}. These datasets
are small enough to support repeated sampling during Phase 1 while still
exercising two distinct failure modes: factual recall and structured
arithmetic reasoning.

The original semantic entropy evaluation \cite{semantic_entropy_nature_2024}
reports results across five datasets: TriviaQA, SQuAD, BioASQ, NQ-Open, and
SVAMP\@. Of these, three---BioASQ, NQ-Open, and TriviaQA---are open-domain
factual question-answering tasks that differ primarily in domain rather than in
task structure, and TriviaQA is the most widely used and the primary reference
dataset in the original experiments. SQuAD is a reading-comprehension dataset
whose original benchmark design includes source passages; Farquhar et al. make
it context-free by withholding those passages, which still leaves a different
dataset origin and prompt assumption from open-domain recall tasks. The
two-dataset scope therefore covers the two qualitatively distinct task
types---open-domain factual recall and short-answer arithmetic---within a
compute budget appropriate for a bachelor-thesis pilot. Expanding to NQ-Open or
BioASQ remains a straightforward extension because both share the same short
free-text answer format and normalization approach as TriviaQA.

The completed runs do not add SQuAD, BioASQ, or NQ-Open; these datasets remain
future extensions that would broaden the evaluation setting beyond the two
reported tasks \cite{rajpurkar_squad_2016,tsatsaronis_bioasq_2015,
lee_nq_open_2019}. TruthfulQA is relevant to broader truthfulness, but it
is not part of the completed pipeline, because the design isolates semantic
clustering on short-answer tasks
\cite{lin_truthfulqa_2022}.

\section{Model Tiers}

\subsection{Phase 1: Exact-Match Baselines}

Phase 1 records exact-match clustering baselines for the evaluated generation
models. The aim is not to maximize semantic-judge quality, but to verify
generation, answer normalization, exact-match clustering, entropy scoring, and
correctness labeling end to end. The recorded Phase~1 runs use Mistral-7B and
Llama-3.1-70B on TriviaQA and SVAMP; Appendix~\ref{app:runs} lists the Slurm
job identifiers. TinyGPU remains a debug option in the repository workflow, but
it is not the source of any reported Phase~1 result
\cite{jiang_mistral_2023,grattafiori_llama3_2024}.

The first NLI backend enters in Phase~2. A DeBERTa-v3 cross-encoder fine-tuned
on NLI is the preferred local semantic judge because it is practical to run and
supplies the entailment, contradiction, and neutral labels needed for
bidirectional semantic clustering \cite{he_debertav3_2021,
sentence_transformers_nli_deberta_v3_base_2022,williams_multinli_2018}.

\subsection{Phase 2: Alex NLI Runs}

Phase 2 repeats the same model--dataset grid with NLI clustering. The primary
Phase~2 runs are executed on Alex, with DeBERTa-v3-base used as the NLI backend
for semantic clustering. The later DeBERTa-v3-large and KLE checks are posthoc
experiments on the Phase~2 outputs rather than separate primary phases. The
important constraint is that Phase 2 introduces no new research question; it
tests whether the Phase 1 ranking behavior survives NLI-defined semantic
clusters.

\section{Sampling Settings}

For each prompt \(x\), the model produces \(M\) sampled answers. All recorded
Phase~1 and Phase~2 runs use \(M=10\), matching the first meaningful
comparison after smoke testing. Each run logs its decoding configuration.

The default generation setting is temperature \(T=0.7\), top-\(p=0.95\),
and a short maximum answer length appropriate for sentence-length
question answering. The completed experiments keep decoding fixed at
\(T=0.7\) and top-\(p=0.95\); temperature sweeps remain future work.

\section{Baselines and Methods}

The minimum baseline is surface-form uncertainty: naive entropy or
diversity over exact or lightly normalized answer strings. It addresses
a single question: does semantic clustering add value beyond the
observation that sampled outputs differ lexically?

The core method is discrete semantic entropy. Phase~1 clusters samples by
exact-match normalization, while Phase~2 uses bidirectional entailment clusters;
in both cases entropy is computed over cluster frequencies
\cite{kuhn_semantic_uncertainty_2023,semantic_entropy_nature_2024}. This is the
first method evaluated. Full
probability-weighted semantic entropy remains outside the completed extension
set.
The released semantic uncertainty codebase serves as a methodological
reference point \cite{kossen_semantic_uncertainty_code_2024}.

Secondary baselines such as SelfCheckGPT-style sampling consistency and P(True)
are relevant comparisons but are not included in the recorded runs
\cite{manakul_selfcheckgpt_2023,kadavath_language_models_know_2022}.

\section{Advanced Metrics and Extensions}

Following the Phase~2 main runs, two posthoc extensions were completed
and are reported in Section~\ref{sec:posthoc}.

\textbf{Kernel Language Entropy (KLE)} replaces hard semantic clusters
with a kernel-based entropy objective computed over sentence-embedding
similarities \cite{nikitin_kernel_language_entropy_2024}.  KLE was run
on all four Phase~2 JSONL output sets (Fritz cluster, posthoc jobs) using
\texttt{sentence-transformers/all-MiniLM-L6-v2}
\cite{sentence_transformers_all_minilm_l6_v2_2022}.

\textbf{DeBERTa-v3-large reclustering} re-ran the Phase~2 NLI
clustering step with a larger cross-encoder
(\texttt{cross-encoder/nli-deberta-v3-large}) to test whether the
70B/TriviaQA regression observed under the base model disappeared with a
larger NLI backend
\cite{sentence_transformers_nli_deberta_v3_large_2022}.

The following extensions were not run within the thesis scope: Semantic
Energy \cite{ma_semantic_energy_2025}, Semantic Volume
\cite{li_semantic_volume_2025}, Adaptive Bayesian semantic entropy
\cite{sun_adaptive_bayesian_semantic_entropy_2026}, and Semantic Entropy
Probes \cite{kossen_semantic_entropy_probes_2024}.  None is required for
the Phase~1 claim or the primary Phase~2 scale-up.

\section{Output Schema}

Each recorded run writes JSONL with one record per prompt. The shared fields
below make generation, clustering, scoring, and evaluation auditable
while leaving extensions free to add method-specific fields:

\begin{verbatim}
{
  "run_id": "string",
  "phase": "phase1|phase2",
  "cluster": "local|tinygpu|alex|helma",
  "prompt_id": "string",
  "dataset": "triviaqa|svamp|...",
  "split": "validation",
  "prompt": "string",
  "reference_answers": ["string"],
  "model": "string",
  "model_tier": "small|7b_8b|70b_plus",
  "decoding": {
    "num_samples": 10,
    "temperature": 0.7,
    "top_p": 0.95,
    "max_new_tokens": 64,
    "seed": 0
  },
  "sampled_answers": ["string"],
  "normalized_answers": ["string"],
  "semantic_clusters": ["integer_per_sample"],
  "cluster_representatives": ["string"],
  "scores": {
    "naive_sample_entropy": 0.0,
    "surface_entropy": 0.0,
    "discrete_semantic_entropy": 0.0
  },
  "entailment_backend": "string",
  "correctness_label": "boolean"
}
\end{verbatim}

Large raw generations, model caches, checkpoints, and full intermediate
outputs are handled by the storage and reproducibility policy in
Chapter 5.

\section{Validation Checks}

Every recorded run is checked against the following structural requirements:

\begin{enumerate}
  \item every prompt has exactly \(M\) sampled answers;
  \item every sampled answer has a normalized form;
  \item every answer receives a semantic cluster identifier, and the
    cluster list contains one identifier per sampled answer;
  \item entropy scores are finite and non-negative;
  \item correctness labels are present for all evaluated prompts;
  \item decoding settings, model names, clustering backend, dataset split, and
    random seeds are recorded;
  \item a small manual audit confirms that several clusters are
    reasonable.
\end{enumerate}

The additional HPC checks for Slurm jobs, cache locations, output paths, GPU
metadata, and failure logging are execution concerns covered in Chapter 5 and
Appendix~\ref{app:experiment-details}.

\section{Evaluation Metrics}

The main evaluation is selective prediction. Each uncertainty score
ranks examples from most to least uncertain. The thesis reports AUROC,
AURAC, and rejection-accuracy curves to measure whether high-uncertainty
examples are more likely to be incorrect. Raw answer accuracy is
reported as context, but it is not sufficient on its own, because the
practical goal is to decide when a model should answer, abstain, or
route the prompt to a more expensive verification procedure
\cite{semantic_entropy_nature_2024}.
