\section{Hallucinations and confabulations}
\label{sec:hallucination-confabulation}

``Hallucination'' covers several failures. A model can be unfaithful to a
source, make unsupported claims, run out of knowledge, reason badly, or guess
because the benchmark rewards guessing over admitting
ignorance~\cite{ji_hallucination_survey_2023,%
huang_llm_hallucination_survey_2023,%
maynez_faithfulness_factuality_2020,%
kalai_why_language_models_hallucinate_2025,%
augenstein_factuality_challenges_2024}. These have different causes and need
different fixes, so no single detector handles all of them.

The semantic entropy paper~\cite{semantic_entropy_nature_2024} isolates one:
\emph{confabulations}, fluent answers that are both wrong and arbitrary.
``Arbitrary'' means the answer changes with things that should not matter, such
as the random seed used to generate it. Confabulations are the method's target.
The evaluation labels whether each answer is correct, without separately
identifying confabulations. Some models are wrong in the same way every time.
That can happen when the training data contains a misconception, when the
problem needs reasoning the model cannot do, or when the benchmark discourages
the model from admitting uncertainty. Such a model gives stable answers, so a
detector based on disagreement between samples cannot find the
error~\cite{simhi_choke_2025,ma_semantic_energy_2025}.

This limit follows directly from what the method measures. It asks how much the
answers disagree when a question is repeated. An error that remains the same
across samples creates no disagreement and therefore no warning signal.

The method relies on a simple expectation. If the model knows the answer,
repeated samples may use different words but should keep the same meaning. If
the model is confabulating, the samples should give conflicting answers.
Uncertainty over meanings should therefore be a better warning signal than
uncertainty over exact strings~\cite{kuhn_semantic_uncertainty_2023,semantic_entropy_nature_2024}.

\section{Uncertainty in free-form generation}
\label{sec:uncertainty-freeform}

When a model picks from a short fixed list, say ``cat'', ``dog'' or ``horse'',
measuring its uncertainty is easy. It assigns a probability to each option, and
those probabilities already say how sure it is. A language model has no such
list. It produces whole sentences, and the same fact can be written many ways
(``Paris'', ``Paris, France'', ``the capital is Paris''), while two sentences
that look almost alike can mean different things. Counting exact word matches
is therefore a poor guide to whether the model is unsure. If the model spreads
its probability across ten ways of stating one fact, token-level scores can
make it look uncertain even though all ten answers mean the same thing.
Sequence-level entropy can mislead for the same reason. This problem motivates
work on uncertainty in natural language
generation~\cite{baan_uncertainty_nlg_2023} and semantic
uncertainty~\cite{kuhn_semantic_uncertainty_2023}.

Three levels of variation are worth keeping apart:

\begin{enumerate}
  \item \emph{lexical variation}: different words for the same thing
    (``Paris'' vs.\ ``Paris, France'')
  \item \emph{semantic variation}: different claims
    (``Paris'' vs.\ ``Lyon'')
  \item \emph{factual correctness}: whether the chosen claim is right.
\end{enumerate}

Semantic entropy works at the second level. It estimates uncertainty over
meanings, not over truth. Deciding whether an answer is correct is a separate
step that compares it against a reference or a
judge~\cite{semantic_entropy_nature_2024}. These two choices can be changed
independently. As the results show, changing the correctness rule can change
the ranking of methods even when their uncertainty scores stay the same.

Recent surveys~\cite{shorinwa_uq_llm_survey_2024,%
liu_uq_confidence_calibration_survey_2025} place these methods within the wider
study of uncertainty in language models. Other approaches use calibration,
confidence stated in words, or the model's internal states. Current benchmarks
compare many of these methods on the same tasks~\cite{lm_polygraph_vashurin_2025}.

\section{Related uncertainty estimators}
\label{sec:calibration-abstention}

An uncertainty score can help decide which answers to reject or check.
The evaluation covers ranking, not calibration: whether incorrect answers
receive higher uncertainty than correct ones.

Several related methods address the same problem without grouping by meaning.
P(True)~\cite{kadavath_language_models_know_2022} asks the model whether its own
answer is correct. It tests what the model can say about its own answer rather
than how much repeated samples vary. SelfCheckGPT~\cite{manakul_selfcheckgpt_2023}
generates several responses and compares them without using an external
database or token probabilities. Semantic entropy also compares samples, but it
first groups answers that mean the same thing before calculating
entropy~\cite{kuhn_semantic_uncertainty_2023,semantic_entropy_nature_2024}.
Chapter~\ref{ch:results} measures whether that extra grouping step improves
the result.

A third family reads the model's \emph{hidden states} instead of its answers.
These internal values can contain information about reliability that is not
clear in the output text. Burns et al.~\cite{burns_latent_knowledge_2023} find a
direction in these values that separates true and false statements without
labels. Azaria and Mitchell~\cite{azaria_internal_state_lying_2023} train a
small classifier to make that distinction, while INSIDE~\cite{chen_inside_2024}
compares the shapes formed by internal sentence representations. Semantic Entropy
Probes~\cite{kossen_semantic_entropy_probes_2024} train a small classifier to
predict semantic entropy from the hidden states. The costly semantic entropy
labels are produced during training. Once trained, the probe can score a single
answer without generating alternatives or making entailment comparisons.
Sections~\ref{sec:sep-method} and~\ref{sec:other-estimators} define this
probe and a version trained to predict correctness.

\section{Semantic equivalence and entailment}
\label{sec:semantic-equivalence}

The key step in semantic entropy is deciding when two sampled answers count as
the same answer. It uses semantic equivalence rather than exact string matches.
In Farquhar et al.'s short-answer method~\cite{semantic_entropy_nature_2024},
two answers are placed together when each entails the other in the context of
the question.
This is a practical test for similar meaning, not a complete definition of it.

Natural Language Inference (NLI) is the standard tool for this comparison. An
NLI model reads two sentences and labels their relation as \emph{entailment}
(the first implies the second), \emph{contradiction}, or \emph{neutral}. Two
answers count as equivalent only when each entails the other.

Two kinds of model make this judgment. The first is a \emph{cross-encoder}
trained on inference data such as MultiNLI~\cite{williams_multinli_2018}. A
cross-encoder reads both sentences together and compares them directly. The
released code loads a DeBERTa model~\cite{he_deberta_2021}, and the experiments
also use the DeBERTa-v3-large cross-encoder~\cite{he_debertav3_2021,%
sentence_transformers_nli_deberta_v3_large_2022}. A \emph{bi-encoder}, in contrast,
reads each sentence separately. A cross-encoder must process each compared pair
together. The second kind is a general instruction-tuned language model that
receives the comparison as a written question.
Qwen2.5-72B-Instruct~\cite{yang_qwen25_2024} fills this role
in place of the proprietary judge used by the original study for
sentence-length answers. Chapter~\ref{ch:semantic_entropy} gives the exact rule
and full list of models.

This test has two important limits. First, its quality depends on the model that
makes the judgment, and the models used here differ greatly in size. Second,
the relation is symmetric because both directions are checked, but it is not
guaranteed to be transitive. Answer $a$ may match $b$, and $b$ may match $c$,
while $a$ does not match $c$. A grouping method must decide what to do in this
case. Section~\ref{sec:clustering} shows that the released code makes the final
groups depend on the order in which the samples arrive.

\section{Research gap}
\label{sec:research-gap}

Earlier studies report that semantic entropy detects confabulations better than
the methods used for comparison, and later work has adopted this
result~\cite{semantic_entropy_nature_2024,kuhn_semantic_uncertainty_2023,%
kossen_semantic_entropy_probes_2024}. Those comparisons raise three questions.

\paragraph{Retesting the method on selected open models.} The
original study uses proprietary judges and older language models. Its released
code~\cite{kossen_semantic_uncertainty_code_2024} also differs from the paper's
description in several small ways. Running the method on selected open models
tests whether the reported improvement remains under the settings used here.

\paragraph{Separating the steps of the method.} The literature
compares semantic entropy with entropy over sequence log-likelihoods,
self-evaluation methods such as P(True)~\cite{kadavath_language_models_know_2022},
and hidden-state probes~\cite{kossen_semantic_entropy_probes_2024}. Each method
differs from semantic entropy in several ways: what it measures, how many model
calls it needs, and whether it groups answers. Later surveys and benchmarks cover
these methods alongside other comparisons~\cite{shorinwa_uq_llm_survey_2024,%
liu_uq_confidence_calibration_survey_2025,lm_polygraph_vashurin_2025}. These
comparisons can show whether the complete method performs better, but they
cannot by themselves show which step causes the difference.

The additional comparison here is simple. Draw the same samples, normalize them, count
the distinct strings, and calculate entropy from those counts. This method
needs no entailment model. Comparing it with semantic entropy tests the added
value of meaning-based grouping, subject to the raw-versus-normalized input
difference explained in Section~\ref{sec:ladder}.
Comparing the estimators described in Chapter~\ref{ch:introduction} also
tests the other steps one at a time.

\paragraph{Testing evaluation choices together.} Every
reported result depends on the entailment model, the correctness rule, and the
sampling temperature. Recent work finds that semantic entropy weakens as
one-sentence outputs become longer~\cite{nguyen_beyond_semantic_entropy_2025}
and includes some temperature tests. The experiments vary these choices within
one evaluation framework. Entailment models and correctness rules can be compared
on the same stored answers, so any change can
be linked to the evaluation choice. Temperature changes the sampled answers and
must therefore be tested in a separate experiment while the other settings are
held fixed. Repeating runs with different random seeds also helps distinguish
consistent changes from variation between runs.

The main study covers three short-answer tasks: open-domain factual recall with
TriviaQA~\cite{joshi_triviaqa_2017} and NQ-Open~\cite{lee_nq_open_2019}, and
arithmetic word problems with SVAMP~\cite{patel_svamp_2021}. The reasons for
choosing these datasets, the prompt construction, and the
reproduced question selection are in
Chapter~\ref{ch:experimental_design}.

Semantic entropy sits between cheap checks of answer wording and expensive
fact-checking. A fair test must keep generation, grouping, correctness scoring,
and evaluation separate so that one can change while the others stay fixed.
Chapter~\ref{ch:semantic_entropy} defines the method in these terms.
