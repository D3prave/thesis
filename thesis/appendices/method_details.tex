\section{Measurement files and reproducibility}
\label{app:schema}
\label{app:reproducibility}

Most result tables and figures are generated by
\path{scripts/build_thesis_tables.py} from
\path{docs/independent_analysis/data/measurements.csv}. The thesis uses rows
marked \texttt{arm = short\_answer} for the main grid and rows marked
\texttt{arm = long\_form} for the biography comparison in
Section~\ref{sec:longform-results}. Each row identifies one prompting
condition, dataset, generator, seed, temperature, entailment model,
correctness rule, and uncertainty method. The seed-variation and grader-agreement
exports provide the corresponding checks. Individual run values remain in
these files. The appendix tables summarize them.

\section{Long-form biography records}
\label{app:longform-details}

The long-form biography evaluation contains three generators, three seeds, and 500 biography
records per generator--seed run. The prompt requests a biography paragraph.
The Qwen judge scores factual claims, and the uncertainty score is computed
over the complete paragraph. The recorded comparison uses exact matching,
DeBERTa-v3-base, DeBERTa-v3-large, and Qwen-72B entailment models. The
strict bidirectional entailment rule is used throughout. Figure~\ref{fig:longform-comparison}
and Tables~\ref{tab:longform}--\ref{tab:longform-by-generator} report the
result.

The records-only intervals are read from
\path{results/paired_bootstrap_longform.csv}, an unchanged copy of the verified
export recorded in commit \texttt{020f3ea}. The analysis script,
\path{src/scripts/paired_bootstrap_bio_records.py}, reuses the AUROC and paired
bootstrap functions in \path{scripts/paired_bootstrap_hierarchical.py}.
It reads saved labeled biography records from
\path{results_sep_v3_bio/phase1/} and \path{results_sep_v3_bio/phase2/} on Alex.
The source paths and file hashes are listed in
\path{results/paired_bootstrap_bio_records_sources.csv}. Labels were checked
against the nine saved Qwen grading files without relabeling any records.
The recorded NLI runs in this biography family also ran on Alex GPUs.

For each of 2{,}000 resamples, with random seed 20260831, the analysis draws
500 biographies with replacement within each generator--seed run. Both
estimators and the correctness label use the same sampled indices. Draws are
independent across runs. It averages the paired AUROC differences over the
three seeds, then equally over the three generators for the pooled result.
The 95\,\% intervals are the 2.5th and 97.5th percentiles of these differences.
All 108 relevant run-level AUROCs match the measurement export at its recorded
six-decimal precision. No resample had an undefined AUROC.

The dataset, generators, and seeds remain fixed. With one dataset and three
dataset--generator units, no unit or hierarchical intervals were computed.
These are the permissive records-only intervals described in
Section~\ref{sec:statistics}, not estimates of uncertainty across
new datasets and generators. The evaluation also uses one correctness judge,
Qwen, which is one of the entailment models.

The retained export supports regeneration of the reported tables and coverage
checks. Reproducing collection from source inputs would require the original
subject list and prepared input files.

The short-answer hierarchical intervals are imported from
\path{results/paired_bootstrap_se_vs_surface.csv}, produced by a separate
record-level analysis. Rebuilding the tables from these exports is not the same
as recomputing every value from raw answers. The local coverage check verifies
the full dataset--generator--seed grid for each recorded configuration and
checks that the imported bootstrap point estimates agree with the measurement
table.

Collection jobs require a pinned code commit and a clean tracked working tree.
Their \texttt{job\_meta.json} records the commit, model, dataset, decoding
settings, seed, input path, and Slurm job identifier. Later processing steps
can record their own revision while retaining the generation revision. The
metadata do not imply that all steps ran at one commit. Reclustering jobs
check the recorded clustering rule, closure rule, input format, and use of
the question against the requested settings. These checks detect configuration
mismatches, not incorrect entailment judgments.

Generation and LLM judging ran on the NHR@FAU Alex GPU cluster, and later
cross-encoder clustering used Fritz CPUs. Raw generations, model caches, and
hidden states are stored separately from the code and result summaries.
Given stored answers, cross-encoder clustering and exact matching are
deterministic. LLM entailment decisions can vary with inference batching.

\section{Collection checks}
\label{app:collection-checks}

\paragraph{Temperature-sweep labels.}
LLM correctness labels are joined by \texttt{prompt\_id} from the main
collection. They are bit-identical across all 108 checked cells, so all sweep
temperatures are evaluated against the same temperature-$0.1$ answer.
Token-F1 instead grades the modal sampled answer because the sweep did not
save a separate most-likely answer. Its accuracy differs from the main run in
all 54 checked cells, by 0.015 on average in absolute terms and at most 0.262.
The reported sweep therefore uses only LLM correctness labels, and its
answer-length fields are not compared across temperatures.

\paragraph{TriviaQA deduplication.}
\label{app:dedup}
The SQuAD-format conversion stores multiple question--context rows for some
questions, and its row-level split places copies of 16 questions in both
training and evaluation. A further nine questions repeat within training and
six within evaluation. Removing duplicate questions leaves 391 training and
378 evaluation questions. The excluded prompts and reasons are listed in
\texttt{dedup\_triviaqa.json}. The same evaluation exclusions apply to every
method, entailment model, grader, and record-level resampling analysis.
NQ-Open and SVAMP contain no repeats in the selected sets.

\section{Bootstrap details}
\label{sec:bootstrap-assumptions}

The saved short-answer paired analysis uses 2,000 resamples. Within each selected
dataset--generator pair, it averages the three seed-level AUROC differences,
then averages over the nine selected pairs. Record resampling keeps the
compared methods paired within a seed cell, but draws question indices
separately across seeds and generators. It neither synchronizes repeated
questions across these cells nor resamples datasets and generators as
separate factors.

A record resample with only one correctness class has undefined AUROC and is
omitted from that draw's average. This can matter when few answers are labeled
correct. Omission rates were not exported. The intervals and bootstrap tail
proportions are conditional on these choices and are not adjusted for
multiple comparisons.

The measurement table can verify paired point estimates, but the original
scored answers are needed to reconstruct record-level intervals. Tests of the
bootstrap code and checks of the exported values are not an independent rerun
of those intervals.

\section{Probe training and saved features}
\label{app:probe-training}

For each training question, the most-likely answer supplies a hidden state.
Ten separate sampled responses supply the discrete semantic entropy target.
The high/low threshold minimizes the sum of squared deviations within the
two entropy groups, following Equation~(5) of
Kossen et al.~\cite{kossen_semantic_entropy_probes_2024}. A logistic-regression
classifier predicts that label from the hidden state. The accuracy probe
instead learns correctness labels. At evaluation time, each probe needs one
answer and its hidden state.

Training is separate for each dataset, generator, and seed, using questions
disjoint from evaluation. Feature choices are fixed rather than tuned on the
evaluation set. The hidden state comes from position
$n_{\mathrm{generated}}-1$, where the stop sequence determines
$n_{\mathrm{generated}}$. An end-of-sequence token need not be present.

A later audit found one missing training hidden state in the NQ-Open
Llama-3.1-70B short-phrase run with seed 42. The reported fits predate the
finding, and the audit does not establish how that record was handled during
fitting. All retained evaluation records have saved features, but the
training-input gap limits exact reproduction of the existing fits.
